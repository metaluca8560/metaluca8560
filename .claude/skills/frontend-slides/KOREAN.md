# 한국어 발표 자료 규칙

슬라이드에 한국어가 들어가면 이 파일을 Phase 2(스타일 미리보기) 전에 읽고, 모든 미리보기와 최종 덱에 적용한다.
원본 스킬에는 없는 내용이다. 2026-09-28 테스트 덱 두 개(밝은 첨삭지 테마, 어두운 터미널 테마)를 만들고 캡처로 확인한 것만 적었다.

## 1. 폰트: 한글이 그려지는 폰트를 모든 글자에 지정한다

`STYLE_PRESETS.md`의 폰트(Clash Display, Satoshi 등 Fontshare 폰트)는 영문 폰트라 한글이 없다.
한글이 없는 폰트만 지정하면 한글은 운영체제 기본 폰트로 떨어져, 컴퓨터마다 다른 모양이 되고 글자 폭도 달라진다.

- 한글 폰트는 Google Fonts에서 고른다. 프리셋 분위기는 색·배경·레이아웃으로 살리고, 폰트만 바꾼다.
- 테스트에서 캡처로 확인한 폰트:

  | 용도 | 폰트 | 주의 |
  |---|---|---|
  | 제목 | `Nanum Myeongjo` 700/800 | |
  | 제목 | `Black Han Sans` | 굵기가 400 하나뿐이다. `font-weight: 400`으로 쓴다 (700을 주면 브라우저가 가짜 굵게를 만든다). 기호(→ ※ · — ①)가 하나도 없다 |
  | 본문 | `IBM Plex Sans KR` 400/500/700 | 테스트한 기호(→ ※ · — ①)가 모두 있다 |
  | 숫자·코드 | `IBM Plex Mono`, `JetBrains Mono` | 한글이 없다. 아래 참고 |

- **코드용(모노) 폰트에는 한글을 넣지 않는다.** 모노 폰트로 지정한 라벨·쪽수·배지에 한글이 들어가면, 한글이 시스템 폰트로 그려진다. 한글 폰트를 두 번째로 붙여도 공백은 모노 폰트 것을 써서 어절 사이가 크게 벌어진다("노션  기록").
  한글이 들어가는 라벨은 본문 폰트로 쓰고, 모노 폰트는 숫자·영문·코드에만 쓴다. 예: `<span class="ko">`로 한글 부분만 본문 폰트를 지정한다. 다른 클래스보다 뒤에 선언되거나 `.slide .ko`처럼 우선순위를 높여야 적용된다.
- 다른 한글 폰트(Gowun Batang, Noto Serif KR, Do Hyeon 등)도 쓸 수 있다. 확인하지 않은 폰트는 5번 스크립트로 확인한다.
- `<html lang="ko">`로 둔다.

## 2. 줄바꿈: 단어 중간에서 끊지 않는다

기본값에서는 "부/딪히는", "한/다"처럼 단어 가운데서 줄이 바뀐다. 슬라이드 기본 스타일에 넣는다:

```css
.slide {
    word-break: keep-all;      /* 한국어: 단어(어절) 단위로만 줄바꿈 */
    overflow-wrap: break-word; /* 줄바꿈할 곳이 없는 긴 영문·URL은 강제로 끊어 넘침 방지 */
}
```

## 3. 글자 수: 한국어 제목은 짧게

테스트에서 잰 값 (폰트를 실제로 불러온 상태, 한글만 연속으로 넣어 한 줄에 들어간 글자 수):

| 폰트 | 제목 영역 폭 | 크기 | 한 줄 |
|---|---|---|---|
| Nanum Myeongjo 800 | 1630px | 72px | 24글자 (공백·쉼표 섞인 실제 제목: 26자는 한 줄, 30자는 두 줄) |
| Nanum Myeongjo 800 | 1630px | 132px | 13글자 |
| Black Han Sans 400 | 1680px | 80px | 25글자 |
| Black Han Sans 400 | 1680px | 132px | 15글자 |

- 제목이 두 줄로 넘어가면 아래 내용이 밀려 넘친다. 줄이기가 먼저, 크기 줄이기는 나중이다.
- 표에 없는 폰트·폭이면 직접 잰다: 제목 요소에 `'가'.repeat(n)`을 넣고 n을 늘리며 높이가 두 줄이 되는 지점을 찾는다.
  이때 `overflow-wrap: break-word`가 켜져 있어야 한다. `keep-all`만 켜져 있으면 공백 없는 글자열은 줄이 안 바뀌고 옆으로 넘쳐서 잘못된 값(테스트에서 59자)이 나온다.
- 본문 줄 간격은 1.5~1.6.

## 4. 기호: 어느 폰트로 그려졌는지 확인한다

폰트에 없는 기호는 운영체제 폰트가 대신 그린다. 캡처에서는 멀쩡해 보여도 컴퓨터마다 모양이 달라질 수 있어서, 눈으로만은 판단하기 어렵다.

- 5번 스크립트가 "지정하지 않은 폰트로 그린 글자"를 알려준다. 테스트에서 ✓, ✕가 이렇게 잡혔다.
- 걸린 기호는 그 기호가 있는 폰트(예: `IBM Plex Sans KR`)를 폰트 목록에 추가하거나, 글자로 풀어 쓴다.
- 기호 위에 취소선(`line-through`)을 긋지 않는다. 긴 대시(—)는 취소선과 높이가 같아서 선에 덮여 빈칸처럼 보인다.

## 5. 캡처 확인: `scripts/check-ko.mjs`

`SKILL.md`의 확인 단계 대신 이 스크립트를 돌리고, 나온 캡처를 눈으로 본다.

```bash
npm i playwright            # 처음 한 번, 실행할 폴더에서
node .claude/skills/frontend-slides/scripts/check-ko.mjs 발표.html [출력폴더]
```

- 슬라이드마다 1280×720 캡처와 폰(390×844) 캡처를 만든다.
- 알려주는 것: 폰트를 불러왔는지, 무대나 `.frame` 밖으로 넘친 요소, 지정하지 않은 폰트로 그린 글자.
- 폰트 서버에 직접 연결할 수 없는 환경(샌드박스 등)을 위해 Google Fonts를 curl로 받아 넘겨준다. 인증서 검사는 끄지 않는다.
- 겹침과 어색한 줄바꿈은 자동으로 못 잡는다. 캡처를 반드시 눈으로 본다.
- 한글 폰트는 용량이 크다(테스트 3종에 약 8.7MB). Google Fonts는 쓰인 글자 범위만 나눠 받아서 온라인에서는 문제없다. 하지만 인터넷이 없는 곳에서 열면 한글 폰트가 적용되지 않으므로, 오프라인 발표는 PDF로 내보낸다.

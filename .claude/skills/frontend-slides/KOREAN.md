# 한국어 발표 자료 규칙

슬라이드에 한국어가 들어가면 이 파일을 Phase 2(스타일 미리보기) 전에 읽고, 모든 미리보기와 최종 덱에 적용한다.
원본 스킬에는 없는 내용으로, 2026-09-28 테스트 덱을 만들며 캡처로 확인한 문제만 적었다.

## 1. 폰트: 한글이 들어 있는 폰트를 지정한다

`STYLE_PRESETS.md`의 폰트(Clash Display, Satoshi 등 Fontshare 폰트)는 영문 폰트라 한글 글자가 없다.
그대로 쓰면 한글만 시스템 기본 폰트로 떨어져 제목이 영문과 한글이 다른 모양으로 섞인다.

- 한글 폰트는 Google Fonts에서 고른다. 프리셋 분위기는 색·배경·레이아웃으로 살리고, 폰트만 바꾼다.
- 테스트에서 캡처로 확인한 조합:
  - 제목: `Nanum Myeongjo` 700/800
  - 본문: `IBM Plex Sans KR` 400/500/700
  - 숫자·코드·라벨: `IBM Plex Mono` 500/600 (한글이 없으므로 한글이 섞이는 곳에는 `IBM Plex Sans KR`을 두 번째로 둔다)
- 다른 한글 폰트(Gowun Batang, Noto Serif KR, Black Han Sans, Do Hyeon 등)도 쓸 수 있지만 이 테스트에서 확인하지는 않았다. 쓸 때는 아래 4번 캡처 확인을 한다.
- 영문 프리셋 폰트를 제목에 꼭 쓰고 싶으면 `font-family: 'Clash Display', 'IBM Plex Sans KR', sans-serif;`처럼 한글 폰트를 바로 뒤에 둔다. 두 폰트의 굵기와 크기 차이가 어색하지 않은지 캡처로 확인한다.
- `<html lang="ko">`로 둔다.

## 2. 줄바꿈: 단어 중간에서 끊지 않는다

기본값에서는 "부/딪히는", "한/다"처럼 단어 가운데서 줄이 바뀐다. 슬라이드 기본 스타일에 넣는다:

```css
.slide {
    word-break: keep-all;      /* 한국어: 단어(어절) 단위로만 줄바꿈 */
    overflow-wrap: break-word; /* 긴 영문·URL은 넘치지 않게 */
}
```

## 3. 글자 수: 한국어 제목은 짧게

제목 영역 폭 1630px(1920에서 좌우 여백 290px), 나눔명조 800, 폰트를 실제로 불러온 상태에서 잰 값:

| 제목 크기 | 한 줄에 들어간 길이 | 확인 방법 |
|---|---|---|
| 72px | 한글만 24글자. 공백·쉼표 포함 제목 26자는 한 줄, 30자는 두 줄 | 캡처로 측정 |
| 132px (표지) | 약 13글자 | 72px 결과로 비례 계산, 직접 재지 않음 |

- 제목이 두 줄로 넘어가면 아래 내용이 밀려 넘친다. 줄이기가 먼저, 크기 줄이기는 나중이다.
- 폰트가 다르면 폭도 다르다. 다른 폰트를 쓰면 5번 방법으로 다시 잰다.
- 본문 줄 간격은 1.5~1.6.

## 4. 기호: 폰트에 없는 글자는 빈칸이 된다

`IBM Plex Sans KR`에서 긴 대시(—)가 빈칸으로 나왔다. 확인하지 않은 기호(〔 〕, ※, ①, 화살표 등)는 쓰기 전에 캡처로 본다.
빈칸이면 글자로 풀어 쓰거나(예: "긴 대시"), 그 기호가 있는 폰트를 폰트 목록 뒤에 추가한다.

## 5. 캡처 확인

`SKILL.md`의 확인 단계(1280×720, 폰 화면 캡처)를 그대로 하되, 폰트가 실제로 불러와졌는지 먼저 본다.

- `document.fonts`에서 지정한 폰트가 `loaded`인지 확인한다. 불러오지 못한 상태의 캡처는 대체 폰트로 그려져서 글자 폭과 줄바꿈이 실제와 다르다.
- 폰트 서버에 접속할 수 없는 환경(샌드박스 등)이면 Google Fonts CSS와 woff2 파일을 `curl`로 받아 Playwright `page.route()`로 대신 넘겨준다. 인증서 검사를 끄는 방식은 쓰지 않는다.
- 한글 폰트는 용량이 크다(테스트 3종에 woff2 약 8.7MB). Google Fonts가 쓰는 글자 범위만 나눠 받기 때문에 온라인에서는 문제없지만, 인터넷이 없는 곳에서 열면 한글 폰트가 적용되지 않는다. 오프라인 발표라면 PDF로 내보낸다.
